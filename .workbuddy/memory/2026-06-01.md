## Web FM 电台项目 — 方案讨论

用户想做一个可部署的 Web 电台：
- 24h 不间断放歌
- 音乐源：网易云解析（用户有 VIP 账号）
- 进入电台的人都能点歌，点歌排队

### 已对齐的关键决策
- 规模：好友圈 <20 人
- MVP：电台体验版（含歌词、弹幕、在线人数、兜底歌单）
- 技术栈：Python 后端（FastAPI + uvicorn + WebSocket + APScheduler）
- 前端：Vue3 + Vite + Pinia + TailwindCSS
- 网易云：独立容器跑 Binaryify/NeteaseCloudMusicApi（Node），与 FastAPI 内网通信
- 数据：SQLite（SQLModel）+ Redis
- 部署：国内云服务器（提醒用户域名需 ICP 备案，否则用非标端口或先海外）

### 同步算法（核心）
- 服务器维护 currentSong + startedAt(ms)
- 客户端连接后 WebSocket 拿到状态，audio.currentTime = (Date.now()-startedAt)/1000
- 切歌前 30s 预取下一首直链（直链有时效，不能长缓存）
- 切歌时服务端广播 song_change 事件

### 队列规则建议
- 每人最多 1~2 首在队列
- 同曲冷却 30 分钟
- 队列空回退到预设兜底歌单
- 跳过：投票/超时

### 风险提示
- 网易云直链解析违反其 ToS，仅限私人小圈子使用，不可商用/公开
- VIP cookie 会过期，需要自动重登或定期更新

### 已确定
- 部署目标：海外 VPS（不备案，80/443 直接走 Caddy + Let's Encrypt HTTP-01）

### 根因 + 修复
- 错误：sqlalchemy.orm.exc.DetachedInstanceError —— current_user 在 session_scope 退出后才被访问 user.id
- 修复：
  1) auth.current_user 与 user_from_token 改为返回 dataclass UserCtx(id, nickname)，在 session 关闭前读完字段
  2) routers/auth.py login 也在 session 内提前读出 uid/nickname 再返回
  3) db.session_scope 的 Session 改成 expire_on_commit=False，作为兜底
- 顺便修了 /api/state 不依赖鉴权确认正常（日志中能看到 current 已成功播放 Running Up That Hill）
